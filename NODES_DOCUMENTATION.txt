                    GLSL NODE EDITOR - NODE DEFINITIONS
                          Complete Reference Guide
================================================================================

This document provides comprehensive documentation for all nodes available in
the GLSL Node Editor. Nodes are organized by category and include detailed
information about inputs, outputs, parameters, and usage.

================================================================================
                              1. DATA TYPES
================================================================================

The following data types are supported for node inputs and outputs:

  f32     - 32-bit floating point number (scalar)
  vec2    - 2D vector (x, y)
  vec3    - 3D vector (x, y, z)
  vec4    - 4D vector (x, y, z, w)
  bool    - Boolean value (true/false)
  int     - Integer number
  dynamic - Type matches the input type

================================================================================
                            2. PARAMETER TYPES
================================================================================

Nodes can have the following parameter types:

  float       - Floating point number input
  int         - Integer number input
  bool        - Boolean checkbox
  string      - Text input
  expression  - Mathematical expression input
  file        - File picker
  select      - Dropdown menu with predefined options
  colorstops  - Color gradient editor
  slider      - Slider with min/max range

================================================================================
                            3. NODE CATEGORIES
================================================================================

Nodes are organized into the following categories:

  Output    - Final output nodes
  Input     - Constants, runtime data, textures
  Field     - Gradients, patterns, noise, shapes
  Math      - Arithmetic, trigonometric, vector operations
  Utility   - Data manipulation, color operations
  Transform - UV coordinate transformations
  Blend     - Signed Distance Field (SDF) operations

Count
--------------------------------------------------------------------------------
Category: Input
Description: A counter that increments on each input pulse, with optional looping

Inputs:
  - pulse (f32): Pulse signal; each rising edge advances the count

Outputs:
  - count (f32): Current count value

Parameters:
  - step (float): Amount added per pulse [default: 1.0]
  - threshold (float): Pulse threshold [default: 0.5]
  - loop (bool): Wrap the count within [min, max] instead of growing [default: false]
  - min (float): Lower bound of the loop range [default: 0.0]
  - max (float): Upper bound of the loop range [default: 10.0]

Usage: Counts pulses. Each time the pulse input crosses the threshold (a rising
edge) the count increases by `step`. Enable Loop to make the count cycle within
the [min, max] range (e.g. step through a fixed number of states). The running
count is maintained on the CPU and streamed to the shader each frame.

--------------------------------------------------------------------------------
Wave
--------------------------------------------------------------------------------
Category: Input
Description: An LFO - one float animated by a sine, triangle, square, saw or
ramp-down wave, optionally locked to a beat

Inputs:
  - sync (f32): Pulse; each rising edge restarts the cycle. Leave it unwired to
    free-run.

Outputs:
  - out (f32): The current value of the wave

Parameters:
  - shape (select): Waveform [options: Sine, Triangle, Square, Saw, Ramp Down,
    default: Sine]
  - frequency (float): Cycles per second [default: 1.0]
  - amplitude (float): Peak value of the wave [default: 1.0]
  - offset (float): Added to the wave, to re-centre it [default: 0.0]
  - phase (float): Phase offset in CYCLES, not radians - 0.25 is a quarter turn
    [default: 0.0]
  - unipolar (bool): Output 0..1 instead of -1..1 [default: false]
  - pulseWidth (float): Square only - fraction of the cycle spent high
    [default: 0.5]
  - syncThreshold (float): Level the sync input must cross to restart the cycle
    [default: 0.5]

Usage: The standard way to animate anything. Wire it into a parameter, or
reference it from an expression (`=node_<id>`), to make that value sweep on its
own - no Time node and no hand-written sin() needed.

By default the output runs -1 to 1 and every shape is phase-aligned with the
sine (all of them cross zero rising at the start of the cycle), so switching
shape keeps the motion in step. Saw and Ramp Down are the exception: a ramp is
defined by its jump, so it runs -1 to 1 (or 1 to -1) across the cycle and starts
at its extreme.

Most things a wave drives - a radius, a mix amount, a brightness - want a
positive value, so turn on Unipolar to get 0..1. The remap happens BEFORE
amplitude and offset, so Amplitude means the same thing in either mode.

Frequency, amplitude, offset, phase and pulse width are all live uniforms: they
can be dragged, keyframed, MIDI/OSC-bound or driven by another node's expression
without recompiling the shader. Shape and Unipolar select which formula is
emitted, so changing them rebuilds the shader.

Two Waves at the same frequency, a quarter cycle apart (phase 0 and 0.25), give
the sin/cos pair that drives circular motion.

SYNC
Wire a pulse into the sync pin - an Audio Analysis kickTrig, a Trigger, a Count,
anything that crosses the threshold - and each rising edge restarts the cycle
from Phase. That is what locks a wave to a beat: without it a 1 Hz wave and a
120 BPM kick drift apart, with it the wave starts fresh on every hit.

It restarts on the EDGE, not while the pulse is high, so a gate held open does
not freeze the wave at its start. Between pulses it free-runs as normal, so if
the pulses stop the wave simply keeps going from wherever it was last restarted.

Detecting an edge means comparing against the previous frame, which a fragment
shader cannot do, so this part runs on the CPU (WaveSyncProcessor) and the
restart instant is streamed to the shader as a uniform - the same arrangement
Hold and Count use. A Wave with nothing wired to sync compiles with no sync term
at all, so free-running costs exactly what it did before.

Random Value
--------------------------------------------------------------------------------
Category: Input
Description: A clock-driven pseudo-random noise value in the range 0 to 1

Inputs: (none)

Outputs:
  - value (f32): Random value (0-1)

Parameters:
  - speed (float): How fast the value churns [default: 1.0]

Usage: Produces a time-varying random value between 0 and 1 (a fract(sin(...))
hash on the GPU clock). Higher speed yields a new-looking value more often.
Distinct from the Generators "Random" node, which is a spatial (UV-based) noise
pattern.

--------------------------------------------------------------------------------
Text
--------------------------------------------------------------------------------
Category: Generators
Description: Draws a string as a texture the graph can sample

Glyphs cannot be generated procedurally in a shader, so the node rasterises its
text on the CPU into a texture and samples that at the incoming UV. Downstream
it behaves like a Texture 2D node.

Inputs:
  - UV: Sampling coordinates (defaults to the fragment UV)

Outputs:
  - Color (vec4): The rendered pixels, including the background
  - Mask (f32): Glyph coverage (the alpha channel), for compositing

Parameters:
  - text (text): The string to draw; Shift+Enter adds a line break. Braces show
                 a live value - see "Showing values" below [default: "TEXT"]
  - decimals (int): Decimal places for values shown by {...}; whole numbers drop
                 the zeros [default: 2]
  - fontFamily (select): sans-serif | serif | monospace | cursive | fantasy.
                 Used when no custom font is loaded [default: sans-serif]
  - fontData (font): A custom font - load a .ttf/.otf/.woff from disk, or pick
                 one installed on this machine. See "Custom fonts" below
  - bold (bool): [default: false]
  - italic (bool): [default: false]
  - size (float): Font size as a fraction of the texture [default: 0.25]
  - lineHeight (float): Line spacing, as a multiple of the font size
                 [default: 1.2]
  - letterSpacing (float): Extra space between characters, in em [default: 0.0]
  - align (select): left | center | right [default: center]
  - autoFit (bool): Scale the text down when it would overrun the texture. Off
                 gives exactly the Size set, and long lines are cut off at the
                 edge [default: true]
  - posX (float): Horizontal placement in the texture [default: 0.5]
  - posY (float): Vertical placement, measured from the bottom [default: 0.5]
  - fit (select): contain | cover | stretch. How the square text texture maps
                 onto a non-square output [default: contain]
  - color (color): Fill colour [default: white]
  - outlineWidth (float): Outline thickness as a fraction of the font size;
                 0 disables it [default: 0.0]
  - outlineColor (color): [default: black]
  - background (color): Fills the whole texture behind the text; alpha 0 leaves
                 it transparent [default: transparent]
  - resolution (int): Size of the rasterised texture, per side [default: 1024]
  - wrap (select): clamp | repeat | mirror. clamp shows nothing outside the
                 texture; the others tile it [default: clamp]
  - filter (select): linear | nearest [default: linear]

Usage: Titles, captions and typographic masks. Wire Mask into a Mix or a
       Multiply to colour or composite the letters, or into a Displacement to
       distort them. Position, scale and rotation of the result are left to the
       Transform nodes - feed one into the UV input, or feed this node into a
       transform's Texture pin.

Showing values: braces inside the text are evaluated and replaced by their
       value, so the node can read out a live signal rather than print the
       reference:

         BPM {node_4}                 another node's output
         {node_4 * 2}                 arithmetic on it
         t={time}  lvl={audioEnvelope}
         =node_4 * 2                  a whole field starting with = is one
                                      expression

       Values refresh on their own about 20 times a second, so a readout tracks
       what it points at. The same expressions work in the numeric parameters
       (Size, Position, ...), which makes those animate too. An expression that
       cannot be resolved yet renders as nothing rather than leaking its source
       text into the frame.

Custom fonts: the font's bytes are stored in the project, not just its name, so
       a shared patch keeps its typeface on a machine that doesn't have the font
       installed. Fonts up to 8MB are accepted. "Installed..." needs the
       browser's permission to read local fonts and is only offered where that
       API exists.

Note: Every parameter is baked into the texture rather than sent as a uniform,
      so an edit redraws the bitmap. Redrawing is skipped when nothing about the
      picture changed, which is what keeps an animated readout cheap.

Aspect: the texture is square and the output usually isn't. "contain" (the
      default) fits the square inside the frame so letters keep their shape,
      "cover" fills the frame and crops, and "stretch" is the uncorrected
      mapping that distorts to fill.

--------------------------------------------------------------------------------
BOOLEAN LOGIC GATES
--------------------------------------------------------------------------------
The logic gates (AND, OR, XOR, NOT, NAND, NOR, XNOR) treat their inputs as
booleans: a value counts as TRUE when it is >= Threshold (default 0.5). Each
gate outputs exactly 0.0 or 1.0, so the result can drive a mask, a Mix factor,
a Select condition or another gate.

They are type-aware and work component-wise: feeding two vec3 masks in gives a
vec3 mask out (each channel gated independently). If the two inputs have
different widths, B is coerced to A's width. An unconnected input reads as
FALSE (0.0).

================================================================================
                              USAGE TIPS
================================================================================

1. Start Simple
   - Begin with a UV node and connect it to simple patterns or textures
   - Use the Output node to see results
   - Add complexity gradually

2. Common Patterns
   - UV → Transform → Pattern → ColorRamp → Output
   - UV → Noise → Displacement → Texture → Output
   - Time → Sin/Cos → Parameter → Animated effect

3. Performance
   - More octaves in noise = slower but more detailed
   - Complex math operations accumulate
   - Texture sampling is relatively fast

4. Color Workflow
   - Use vec3 for RGB colors (0-1 range)
   - Use vec4 when alpha channel is needed
   - Convert between RGB and HSV for easier color manipulation

5. Animation
   - Use Time node for continuous animation
   - Multiply Time by a constant to control speed
   - Use Sin(Time) for oscillating values

6. Distance Fields
   - Combine shapes using Blend nodes
   - Use smoothness parameters for organic effects
   - Threshold distance fields to create hard edges

7. UV Manipulation
   - Apply transforms before sampling textures/patterns
   - Use polar coordinates for radial effects
   - Displacement creates organic distortions

8. Debugging
   - Use UVToColor to visualize coordinate spaces
   - Connect intermediate values to Output to inspect them
   - Clamp/Saturate values to ensure they're in expected ranges
